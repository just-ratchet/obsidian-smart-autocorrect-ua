# Як долучитися

Дякуємо, що хочете покращити Smart Autocorrect UA!

## Повідомити про помилку

Створіть [issue](../../issues/new/choose) і вкажіть: версію плагіна, версію Obsidian, платформу (комп'ютер чи телефон), що ви набирали, що очікували й що сталося. Приклад тексту, у якому виправлення спрацювало хибно, дуже допомагає.

## Запропонувати зміну

1. Форкніть репозиторій і створіть гілку.
2. Потрібні Node.js 22+ і [pnpm](https://pnpm.io): `pnpm install`.
3. Внесіть зміни та запустіть перевірки:
   ```bash
   pnpm typecheck
   pnpm test
   pnpm format
   pnpm mobile:check
   ```
4. Створіть pull request з коротким описом змін.

## Переклад і тексти

- Усі видимі користувачеві рядки живуть у `src/predictive/i18n.ts`: ключ додається в `en` (джерело ключів) і в `uk` (те, що бачить користувач).
- Не пишіть рядки прямо у виклики `setName`, `setDesc`, `Notice` тощо: тест `test/i18n.test.ts` це перевіряє.
- Дотримуйтесь чинного правопису (редакція 2019 року) та єдиної термінології: одна дія — одна назва.

## Правила автокорекції

Правила лежать у `src/predictive/engine/text/`. Кожна зміна поведінки має супроводжуватися тестом у `test/` із парою «вхід → очікуваний результат»; окремо додавайте випадки «не чіпати» (код, посилання, вікі-посилання, YAML, англійський текст).

## Випуск (для власника)

1. `node version-bump.mjs X.Y.Z`, запис у `CHANGELOG.md`.
2. Створіть тег `X.Y.Z` (без префікса `v`) і надішліть його: workflow `.github/workflows/release.yml` збере плагін і створить GitHub Release з `main.js`, `manifest.json`, `styles.css`.
3. Файли мовних моделей (`word_lstm.bin`, `predictive-global.bin`, `wordlist.bin`) лежать в окремому релізі з тегом `RELEASE_TAG` з `src/predictive/ModelAssets.ts`; перед змінами моделей оновіть цей тег і контрольні суми.
